# ReferenceCity

> 合成国土空間計画ベンチマーク都市

[中文](README.md) | [English](README.en.md) | [日本語](README.ja.md)

ReferenceCity は UrbanPlanningLab の標準合成実験都市です。現実都市の複製ではなく、実証的ケーススタディの代替でもありません。制御可能・再現可能で Ground Truth が既知の空間・ガバナンス環境を提供し、国土空間計画関連のデータモデル、アルゴリズム、トラストチェーン、研究方法を安定して検証するための基準都市です。

## 現在の課題：Phase 1

**第一段階は国土空間トラストチェーン研究だけを優先して支援します。**

最初の目標は、小規模で人間が直接確認でき、かつ完全な計画ライフサイクルを持つ実験都市を構築し、以下を検証できるようにすることです。

- 空間オブジェクト登録と安定 ID；
- 計画成果と版管理；
- 作成、提出、承認、発効、変更等のイベント；
- 組織、役割、権限、複数主体による操作；
- データ指紋 / Hash と文書完全性；
- 権限外編集、文書改ざん、空間競合等の異常シナリオ；
- 履歴状態と再現可能な回帰テスト。

Phase 1 では、現実都市らしい視覚表現や百万件規模の要素数は目標にしません。

## 単なる「架空の地図」ではありません

ReferenceCity は相互に関連する五つのデータ領域から構成されます。

1. **Spatial State** — 行政単位、道路、水系、区画、建築物等；
2. **Planning State** — 計画単位、用途、規制指標、境界、制約；
3. **Governance State** — 組織、役割、権限、文書、承認関係；
4. **Event History** — 作成、提出、承認、変更、撤回、異常操作等の時系列；
5. **Ground Truth** — 各ベンチマークシナリオに事前定義された正しい結果。

したがってシナリオは「どこに何があるか」だけでなく、「誰が、いつ、どの規則に基づいて何を行い、正しい結果が何か」まで記述します。

## Phase 1 初期規模

最初の版は小さく、検証しやすい規模を優先します。

- 1 都市；
- 3 区レベル単位；
- 6–10 街道・鎮レベル単位；
- 約 50–100 計画区画；
- 約 100–300 建築物・施設等；
- 5–10 組織・役割；
- 20–40 計画ライフサイクルイベント；
- 10–20 正常・異常ベンチマークシナリオ。

性能試験用の大規模データは後に生成器で別途作成し、人間が検証できるコア都市を汚染しないようにします。

## UrbanPlanningLab との関係

- [UrbanPlanningLab](https://github.com/KiYouJyo/UrbanPlanningLab) が共通研究意味モデル、用語、長期研究基盤を定義します。
- ReferenceCity はそれらの共通規約を一つの標準合成都市として実装します。
- ReferenceCity が逆に共通研究モデルを決めることはありません。
- トラストチェーン本体に ReferenceCity 固有の例外をハードコードしません。

## 長期ビジョン

Phase 1 安定後、単位大院、高層閉鎖型住宅団地、小街区、伝統街路、城中村、TOD、新城、工業地区、都市農村境界部、村落等の形態プロトタイプを段階的に追加し、人居形態、都市更新、TOD、都市農村ガバナンス研究に利用できるようにします。

これらは将来互換性のための目標であり、現在は国土空間トラストチェーン研究を最優先とします。
